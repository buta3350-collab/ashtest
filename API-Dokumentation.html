01 — Architektur

Architektur-Überblick

Die Website nutzt zwei separate API-Routen um Fahrzeugdaten zu laden. Die Fahrzeugliste wird beim Seitenladen einmalig abgerufen. Die Fahrzeugdetails (Beschreibung, Ausstattung, Farbe usw.) werden erst geladen wenn ein Benutzer ein Fahrzeug im Modal öffnet — sogenanntes Lazy Loading.

02 — Datenquellen

Datenquellen

Quelle A — Willhaben (inoffizielle Search API)

Willhaben stellt keine offizielle öffentliche API für Händler bereit. Die Website nutzt dieselbe interne JSON-Schnittstelle, die auch der Willhaben-Browser selbst aufruft. Diese Methode ist technisch sauber, kann sich aber ändern wenn Willhaben ihre Infrastruktur umstellt.

GET https://www.willhaben.at/webapi/iad/classified/iad/classified/search/result.json
Parameter: ADVERTISER_ID=1003686  |  rows=200  |  isSearchPage=true  |  sort=1

Liefert: Alle Inserate des Händlers mit Titel, Preis, Kilometer, Kraftstoff, Getriebe, Leistung, Bilder, Farbe, Ausstattung (Codes), Karosserie, Antrieb, Türen, Sitze, Vorbesitzer, Zustand, gekürzte Beschreibung.

Hinweis: Willhaben kürzt die Beschreibung absichtlich in den Suchergebnissen (Anti-Scraping). Vollständige Beschreibungen kommen daher von Quelle B.

Quelle B — motornetzwerk.at (Willhaben Partner)

motornetzwerk.at ist ein offizieller Willhaben-Partner. Autocenter Shabani hat eine eigene Händlerseite unter autocenter-shabani.motornetzwerk.at. Diese Seite bietet PHP-Proxy-Endpunkte die vollständige Fahrzeugdaten liefern — inklusive kompletter HTML-Beschreibung und voller Ausstattungsliste.

GET https://autocenter-shabani.motornetzwerk.at/app/php-wrappers/php-wrapper.php
Parameter: aid=1003686 — Liefert alle PKW als Liste  |  aid=1003686&vid={ID} — Liefert Volldetails eines Fahrzeugs
GET https://autocenter-shabani.motornetzwerk.at/app/php-wrappers/php-wrapper-truck.php
Parameter: aid=1003686 — Liefert alle Nutzfahrzeuge (Transporter, Vans)
Wichtig: aid = Advertiser ID des Händlers = 1003686. Diese ID ist identisch mit der Willhaben Seller-ID in der .env.local.
03 — Endpunkt

/api/vehicles

Diese Route lädt alle Fahrzeuge für den Grid auf der Verkaufsseite. Sie wird beim ersten Seitenaufruf einmalig aufgerufen.

Ablauf

1. Aufruf der Willhaben Search API mit ADVERTISER_ID=1003686
2. Falls die JSON-API fehlschlägt: Fallback auf HTML-Seite + __NEXT_DATA__ Parsing
3. Rohdaten werden durch parseDealerAds() in das WillhabenCar-Format konvertiert
4. Rückgabe als JSON an den Browser

04 — Endpunkt

/api/vehicle-desc

Diese Route liefert die vollständigen Details eines einzelnen Fahrzeugs — inklusive kompletter Beschreibung, voller Ausstattungsliste und aller technischen Daten die in der Listenansicht nicht enthalten sind. Sie wird erst aufgerufen wenn der Benutzer ein Fahrzeug im Modal öffnet (Lazy Loading).

GET /api/vehicle-desc?id={willhaben_ad_id}
Beispiel: /api/vehicle-desc?id=863385416

Wie die ID entsteht

Die id ist die Willhaben-Inserat-ID (z.B. 863385416). Diese ID kommt aus dem /api/vehicles Endpunkt und ist identisch mit der Willhaben-Anzeigen-ID. motornetzwerk.at verknüpft dieselben IDs da sie dieselben Willhaben-Daten verwenden.

05 — Datenfluss

Datenfluss & Sequenz

Schritt 1 — Seite laden

Browser → /api/vehicles → Willhaben Search API

Browser lädt verkauf-Seite
  → fetch('/api/vehicles')
    → Willhaben API: .../search/result.json?ADVERTISER_ID=1003686
      → parseDealerAds(rawData)
        → Array<WillhabenCar> (alle Felder, Beschreibung gekürzt)
  ← JSON { cars: [...] }
← Grid mit allen Fahrzeugen angezeigt

Schritt 2 — Fahrzeug öffnen (Lazy Load)

Benutzer klickt Auto → Modal → /api/vehicle-desc → motornetzwerk.at

Benutzer klickt auf Fahrzeug (z.B. id: "863385416")
  → CarDetailModal öffnet
  → useEffect([car.id]) wird ausgelöst
    → fetch('/api/vehicle-desc?id=863385416')
      → motornetzwerk.at: php-wrapper.php?aid=1003686&vid=863385416
        → JSON mit vollständigen Details
      → HTML-Beschreibung wird bereinigt
    ← { description, equipment, color, doors, ... }
  ← Modal zeigt vollständige Beschreibung + Ausstattung

Schritt 3 — Caching beim nächsten Klick

Gleiches Auto nochmal öffnen: Next.js Cache greift

Benutzer öffnet dasselbe Auto (id: "863385416")
  → fetch('/api/vehicle-desc?id=863385416')
    → Next.js Cache (revalidate: 3600s) → kein neuer Request
    ← Sofortige Antwort aus Cache
  ← Modal sofort vollständig

07 — Caching

Caching-Strategie

EndpunktMethodeDauerBegründung
/api/vehicles (JSON API)cache: 'no-store'Kein CacheNeue Inserate sofort sichtbar
/api/vehicles (HTML Fallback)revalidate: 3005 MinutenHTML-Seite ändert sich selten
/api/vehicle-descrevalidate: 36001 StundeFahrzeugdetails ändern sich kaum
Next.js fetch-Cache: Das next: { revalidate: N } Attribut aktiviert den eingebauten Next.js Data-Cache. Nach Ablauf der Zeit wird beim nächsten Request neu von der externen API geladen, im Hintergrund, ohne den Benutzer warten zu lassen (Stale-While-Revalidate).
08 — Fehlerbehandlung

Fehlerbehandlung & Fallbacks

/api/vehicles — Zwei-Stufen-Fallback

StufeVersuchBei Fehler
1Willhaben JSON Search API→ Weiter zu Stufe 2
2Willhaben HTML-Seite + __NEXT_DATA__ Parsing→ Fehler-Response: { error: "...", cars: [] }

/api/vehicle-desc — Graceful Degradation

Falls motornetzwerk.at nicht erreichbar ist oder für die ID keine Daten liefert, wird { description: '', equipment: [] } zurückgegeben. Das Modal zeigt dann die (ggf. gekürzte) Willhaben-Beschreibung aus der Fahrzeugliste.

09 — Backup

Backup & Wiederherstellung

Das originale Willhaben-API-Skript ist gesichert unter:

auto-shabani-nextjs/
  backup-api/
    route.willhaben-unofficial.ts   ← Original Willhaben-Implementierung
    API-Dokumentation.html          ← Diese Dokumentation

Wiederherstellung

Falls die aktuelle Implementierung ersetzt werden muss:

# PowerShell — Original-Route wiederherstellen
Copy-Item backup-api\route.willhaben-unofficial.ts `
          app\api\vehicles\route.ts -Force
Hinweis: Die Willhaben-Backup-Route ist vollständig funktionsfähig und kann jederzeit ohne weitere Anpassungen reaktiviert werden. Sie enthält eigene Farbcode-Mappings, Equipment-Code-Übersetzungen und HTML-Parsing-Logik.
